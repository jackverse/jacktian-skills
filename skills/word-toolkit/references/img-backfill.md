# 专题:::IMG:: 截图占位框回填真实图片

build_docx.py 生成的文档里,`::IMG::题注` 是一个"灰字【截图占位:题注】的单格边框表 +
框下方居中题注段",等真实截图就绪后批量回填。回填是机械活,**唯一的坑在题注匹配**。

## 用脚本(推荐)

```bash
python scripts/fill_img_placeholders.py 文档.docx \
  --img "系统总体结构图=shots/arch.png" --img "功能模块图=shots/modules.png" \
  [--width 14] [--dry-run]
```

- 先 `--dry-run` 看匹配报告,确认无"未匹配"再真跑。
- 退出码 1 = 还有占位框没回填或键名对不上(文件仍已保存,可分批迭代)。
- 依赖仅 python-docx;图片宽默认 14cm(A4 版心内),可 `--width` 调。

## 题注匹配纪律(核心教训)

- 占位文字必须用正则 `【截图占位：(.+?)】` 提取**完整题注**后做**全等**匹配。
- **严禁子串包含匹配**:拿题注去 `cell.text` 里做 `in` 判断,"系统总体结构图"会误命中
  "大赛系统总体结构图"的占位框——两个框被填进同一张图,而且错的那个还覆盖了正确文字。
- 同理,键名表(题注→图片路径)维护后先 dry-run 对一遍账,比回填完再逐页目检便宜得多。

## 手工要点(不用脚本时照此实现)

1. 遍历 `doc.tables` 顶层表格(占位框是 build 生成的顶层单格表;合并单元格按 `_tc` 去重)。
2. `re.search(r"【截图占位：(.+?)】", cell.text)` 提取题注,与图片映射**全等**比对。
3. 回填:清空占位单元格**全部段落 runs**(保留段落对象)→ 段落居中 →
   `p.add_run().add_picture(path, width=Cm(14))`;多余段落删除,只留首段。
4. 占位框**下方的题注段保持不动**(它不属于占位框单元格)。
5. 回填后按 template-generate.md 的渲染校验流程出 PDF/PNG 逐页目检一遍。

## 时机建议

- 占位框先出文档、评审定稿后一次性回填,避免"改一图重建一次"。
- 回填后再要改内容时:**改 md 源重新 build + 重新回填**(回填映射留档),不要在回填版上
  手改正文——手改在下次重建时必丢。
