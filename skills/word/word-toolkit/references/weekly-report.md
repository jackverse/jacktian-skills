# 专题:验收周报系列按阶段日历批量生成与校验

多周成套的周报系列,本质是"同一模板 × 每周事实切片",版式走 template-generate 管线即可;
真正的难点是**时间轴校准**——报告日期、阶段宣称、计划内容必须与真实日历和材料证据一致,
错一处就是"提前宣称完成"或"假期里干活"的硬伤。

## 1. 每周内容从提交史取材

- `git log --since <周起> --until <周止> --pretty` 取每周提交主题,按模块/变更类型分类
  汇总成该周"本周工作";数量表述(提交数、覆盖模块数)来自实际统计,不凭印象编。
- 阶段表述(开发/系统测试/性能/安全/回归/试运行/培训/验收确认)要有材料依据:
  提交记录、测试记录、会议纪要能支撑到哪个阶段就写到哪个阶段。

## 2. 日期校准(最易翻车)

- **报告日期必须避开节假日与周末**;调休上班日要当工作日排进日期序列。批量排期前先拉
  当年放假安排,对每个报告日期做核对,不要按"每周加 7 天"盲推。
- 报告周期跨假期的,**假期情况要在报告周期文字中注明**(如"本周期含法定假期 X 天"),
  否则工作量与周期对不上,评审一眼看出破绽。

## 3. 阶段宣称与下周计划

- **未来日期只能写进"下周计划",绝不能写成已完成**。"已完成/已上线/已通过"的日期一律
  不得晚于该份报告的日期。
- 同模板逐周生成时,"下周计划"要**按该周报告日期做覆盖式定制**,不要把上一周的计划段
  原样带到下一周(日期与事项都应对齐该周节点)。

## 4. 成套 QA 脚本断言(不要逐份目测)

批量生成 N 份后写脚本统一断言,任一不过即列出文件与原因:

| 断言 | 内容 |
|------|------|
| 文件名日期序列 | 严格递增,间隔符合报告周期(如 7 天);命名格式一致 |
| 日期合规 | 每份报告日期不落节假日/周末(调休上班日列白名单) |
| 关键阶段句命中 | 各周应出现的阶段表述用 grep/正则逐一命中 |
| 未提前宣称 | 全文"已完成/通过/上线"等表述的日期不得晚于报告日期;未来日期只允许出现在计划段 |
| PDF 页数范围 | 转 PDF 后页数在模板基准页数 ± 少量浮动内,超出即版式异常 |

渲染校验沿用 template-generate 工作流:`word2pdf.py` 先更新域再导 PDF →
`pdf2png.py --footers` 校验页码单调递增。
