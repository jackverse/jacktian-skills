# 专题:操作手册写作纪律(操作流程与截图占位)

面向系统操作手册(用户操作手册/后台管理手册)的**内容写作**纪律,与 build_docx 的
`::IMG::` 占位机制配套:img-backfill.md 管"占位框怎么回填",本专题管"占位该留哪些、
留多少、题注怎么起名,以及操作流程怎么写才不算偷工"。写源 md(内容阶段)时就按本
专题设计,不要等评审被打回再返工。

## 纪律一:同类操作必须各自独立成完整流程

操作手册中功能相似的操作(如后台的需求审核、融资项目审核、贷款申请审核、入驻审核,
页面布局与按钮雷同),**每一类都必须写成独立的完整操作流程**:

> 进入页面(菜单路径) → 筛选/搜索 → 查看详情 → 通过/退回操作 → 填写备注/意见 → 结果去向

**禁止省略写法**:"操作方法同 XX 一节""步骤类似,不再赘述"等一律不允许。
用户明确要求"长得一样也要每个都有独立操作流程"——评审方按节逐一核对操作步骤,
"同上"在他们看来就是该节缺失。

- 通用章节(如"审核操作通用说明")只做概览与注意事项(审核规则、状态流转、
  公共约定),**不替代**各节的完整步骤;写了通用章,各节仍要写全。
- 差异点恰恰是各节的价值所在:即使流程雷同,各节的筛选项、字段、按钮文案、
  退回后的去向往往不同,省略写法会把这些差异一起省掉。

## 纪律二:截图占位充足且可指导回填

`::IMG::` 占位不是"随手插几个",写源 md 时按下面三条设计。占位符形态为
`::IMG::题注`(生成后是"灰字【截图占位:题注】单格边框表 + 居中图题段");
回填者据题注找页面截图,题注不合格 = 回填靠猜 = 截错图。

1. **每个关键操作节至少一个占位**;凡描述按钮操作的节,题注应注明含哪个按钮,
   如"认证审核(通过/退回按钮)""贷款产品发布(暂存/提交按钮)"——回填者据此
   截带按钮的页面,而不是截一张没有按钮的列表页交差。
2. **用户端(门户)手册凡涉及审核/审批状态的业务**(认证、贷款、入驻、报名、
   融资项目、信息发布等),必须同时有两个占位:
   - "XX 审核通过显示"
   - "XX 审核不通过显示(退回原因)"
   正文同步说明两种状态各显示什么:通过后展示什么内容/状态标识;不通过时
   退回原因出现在哪个位置、能否修改后重新提交。
3. **登录等有多种方式的,每种方式单独占位**(如"UKey 登录""账号密码登录"),
   不能一个占位糊弄多种方式。

## 与回填的衔接

- 题注命名直接决定回填匹配质量(全等匹配纪律见 img-backfill.md);本专题约束
  命名内容本身:名称具体到按钮/状态,同一业务多种状态各起各的名,不共用题注。
- 对账/校验时把占位也当内容查:按节清单核对"关键操作节是否都有占位",
  门户审核类业务检查是否成对出现"通过显示/不通过显示"两个占位。
